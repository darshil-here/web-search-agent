## Proposal — Milestone 2 file plan

Small diff, no rewrite, no second tool.

**New `db.ts` (~90 lines)**
```sql
CREATE TABLE turns (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  role       TEXT NOT NULL,              -- user | assistant
  content    TEXT NOT NULL,
  created_at TEXT NOT NULL,              -- UTC ISO-8601, written by code

);
CREATE INDEX turns_session ON turns(session_id, id);
CREATE INDEX turns_local_date ON turns(local_date);
```
`local_date` is not in your spec. Add it: it is one column that makes date recall exact instead of a UTC-offset guess (see Risks). Functions: `openDb()`, `saveTurn()`, `turnsOnDate(sessionId, date)`, `recentTurns(sessionId, n)`, `datesWithTurns(sessionId)`.

**New `dates.ts` (~70 lines)** — `parseDateRefs(text, now)` handling `yesterday`, `today`, `last Tuesday`, `3 November`, `November 3`, `2026-11-03`, `3 Nov`. Returns `{ label, date }` or `null`. Pure function, unit-testable, no model involved.

**Changed `agent.ts`** — wrap `turn()` in a stdin REPL instead of `process.argv[2]`; accept `SESSION_ID` from env or generate one; before each model call, run `parseDateRefs` and inject the result as a **notebook block** in the input:
- turns found → their verbatim text with timestamps
- date resolved, no turns → literal `NOTEBOOK: no turns on 2026-11-03.` so abstention is grounded rather than inferred
- no date ref → last 10 turns of the session

Recall is a deterministic pre-model retrieval step, not a tool. That keeps the schema at exactly one tool (the §10 rule) and is the defensible architecture point: *the notebook is read by the loop, not by the model's discretion.*

**Changed `trace.ts`** — add `sessionId` and a `recall` event (parsed dates, rows returned, bytes injected). Also fix `verdict: unset` and log the post-step bound so the blank-answer bug becomes visible in traces.

## Risks

1. **Timezone will bite date recall.** Traces prove it: filename `2026-11-17-000220-…`, JSONL `ts: 2026-11-16T18:32Z`. You're at UTC+5:30, so for 5.5 hours a day the local date and UTC date disagree. If you store UTC and inject the local `{{DATE}}`, "what did I ask you yesterday" is wrong for a turn made at 00:30 local. Decide now: store UTC for ordering, `local_date` for matching, and say so in `DESIGN.md`. Retrofitting this means re-deriving dates from timestamps you no longer have the offset for.
2. **A one-shot CLI is not "a chat agent we can talk to."** This is the biggest unlisted gap. The brief's own test set says "what did I ask you on 3 November" — that presupposes a conversation that has been going on. Milestone 2 is not "extend `agent.ts`", it's "give the agent a session". Do the REPL first; everything else hangs off it.
3. **`reasoning: { effort: "low" }` is model-coupled.** Swap `MODEL` to a non-reasoning slug and every call 400s. Guard it or derive it from the slug.
4. **`traces/` is gitignored but cited.** Either commit a curated `traces/` subset or stop citing paths in `FAILURES.md`. A judge who checks one citation and finds a dangling path discounts the whole document.
5. **Silent step-bound exhaustion** — an empty answer with exit code 0 will read as a broken demo, and it's the failure most likely to happen on a hard multi-vendor question.
6. **Snippet-only search caps quality.** Tavily snippets are the ceiling on F-002/F-003 until the tool fetches pages. Don't try to fix grounding by prompting harder; that's how you get 25 confident cells again.
7. **No typecheck in CI/dev loop.** `strict: true` buys nothing while only `tsx` runs. Add `"typecheck"` now, before there's code worth checking.
